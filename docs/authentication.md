# Руководство по архитектуре и настройке аутентификации ONE TEAM

## 1. Концепция Local-First и роль Supabase Auth

ONE TEAM спроектирован по архитектурному принципу **Local-First**:
- **Supabase Auth** используется **исключительно** для управления глобальной цифровой идентичностью (Email/Password, верификация почты, сброс паролей).
- **Все бизнес-данные** (задачи, проекты, финансы, клиенты, стратегия, комментарии и напоминания) хранятся **локально на устройстве** в браузере с использованием базы данных **IndexedDB** и быстрого кэша `localStorage`.
- В Supabase **нет** бизнес-таблиц PostgreSQL, и данные не отправляются во внешнее облако.
- При выходе из сеанса локальные данные в IndexedDB сохраняются и не удаляются.

## 2. Настройка проекта Supabase

1. Зарегистрируйтесь на сайте [supabase.com](https://supabase.com) и создайте новый проект (например, `ONE-TEAM-Auth`).
2. В панели управления перейдите в **Project Settings -> API**.
3. Скопируйте параметры:
   - **Project URL**
   - **Project API Keys -> anon / public key**
4. В корне репозитория создайте файл `.env` на основе `.env.example`:

```bash
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-actual-anon-key-here
```

---

## 3. Настройка почты и перенаправлений (Redirect URLs)

В панели управления Supabase перейдите в **Authentication -> URL Configuration**:
- **Site URL**: укажите адрес вашего приложения (например, `http://localhost:3000` в разработке или URL боевого сервера).
- **Redirect URLs**: добавьте:
  - `http://localhost:3000/#type=recovery` (для восстановления пароля)
  - `https://your-production-domain.com/#type=recovery`

В разделе **Authentication -> Email Templates**:
- Настройте шаблоны писем верификации (`Confirm signup`) и восстановления доступа (`Reset password`).

---

## 4. Первый запуск и назначение роли Владельца (Owner Bootstrap)

- Первый успешно зарегистрированный и подтверждённый пользователь в чистой локальной базе автоматически становится **Владельцем (Owner)** пространства.
- Обычные пользователи не могут выбрать повышенную роль на форме регистрации.
- Состояние инициализации сохраняется в локальной конфигурации (`oneteam_bootstrap_completed_v1`).

---

## 5. Ограничения локального режима

- Поскольку бизнес-данные хранятся в IndexedDB текущего браузера:
  - Вход с другого устройства или другого браузера не переносит локальные задачи и сделки автоматически.
  - Совместная работа между независимыми устройствами без ручного экспорта резервной копии не синхронизируется.
  - Для переноса данных между устройствами используйте встроенный функционал **Резервное копирование и экспорт** в разделе «Настройки -> Синхронизация».
