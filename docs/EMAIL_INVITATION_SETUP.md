# Настройка Email-уведомлений о приглашениях в ONE TEAM

В ONE TEAM реализована система приглашений, основанная исключительно на email-адресе пользователя:
- Никаких публичных ссылок, токенов в URL или magic links.
- Письмо содержит официальное уведомление и понятную инструкцию войти или зарегистрироваться в ONE TEAM с приглашённым email.
- Принятие и отклонение приглашения доступно только авторизованному владельцу подтверждённого email внутри защищённого личного кабинета ONE TEAM через атомарные SQL RPC.

---

## 1. Архитектура безопасности

Отправка уведомлений о приглашениях выполняется через Supabase Edge Function:
`supabase/functions/send-invitation-email/index.ts`

### Механизмы защиты Edge Function:
1. **Проверка авторизации вызывающего**: Функция требует заголовок `Authorization: Bearer <jwt>` и проверяет сессию через Supabase Auth.
2. **Проверка прав в пространстве**: Вызывающий должен быть активным участником с ролью `owner` или `admin` в целевом рабочем пространстве.
3. **Проверка существования записи в БД**: Функция сверяет параметры с реальной записью `pending` приглашения в таблице `workspace_invitations`. Отправка произвольных писем через публичный вызов запрещена.
4. **Защита от XSS/HTML Injection**: Все пользовательские поля экранируются перед подстановкой в HTML-шаблон письма.
5. **Прозрачность доставки**: Функция не рапортует об успехе, если провайдер не подтвердил доставку (возвращается реальный статус и `messageId`).

---

## 2. Настройка провайдера Resend

1. Зарегистрируйтесь на [resend.com](https://resend.com) и подтвердите ваш домен отправки.
2. Получите API ключ в личном кабинете Resend (`re_...`).
3. В Supabase Dashboard перейдите в **Project Settings -> Edge Functions -> Secrets** (или через CLI: `supabase secrets set`):
   ```bash
   RESEND_API_KEY=re_123456789...
   SENDER_EMAIL="ONE TEAM <notifications@yourcompany.com>"
   ```

---

## 3. Деплой Edge Function в Supabase

Для публикации функции в проекте Supabase выполните команду **без** флага `--no-verify-jwt`:

```bash
# 1. Авторизация в Supabase CLI
supabase login

# 2. Привязка проекта
supabase link --project-ref dshlppccurayjfusbcqf

# 3. Установка секретов
supabase secrets set RESEND_API_KEY="re_..." SENDER_EMAIL="ONE TEAM <notifications@yourcompany.com>"

# 4. Деплой защищённой функции (проверка JWT включена)
supabase functions deploy send-invitation-email
```

---

## 4. Поведение при отсутствии настроенного провайдера

Если `RESEND_API_KEY` ещё не настроен в секретах Supabase:
- Функция возвращает понятный статус `{ success: false, error: 'EMAIL_PROVIDER_UNCONFIGURED' }`.
- Система **не имитирует** отправку письма: в интерфейсе отображается информационный блок о том, что приглашение надёжно сохранено в базе данных.
- Приглашённый пользователь, войдя или зарегистрировавшись с этим адресом и подтвердив email, сразу увидит приглашение в разделе «Приглашения» центра уведомлений.

## 5. Применение SQL Миграции 004

Примените миграцию `supabase/migrations/004_invitation_security_hardening.sql` в **SQL Editor** Supabase Dashboard:
- Блокирует прямой `UPDATE` таблицы `workspace_invitations` для обычных участников (запрет обхода RPC).
- Усиливает атомарную функцию `accept_workspace_invitation`:
  - Проверяет `email_confirmed_at IS NOT NULL` (неподтверждённые аккаунты не могут принять приглашение);
  - Проверяет срок действия (`expires_at > now()`);
  - Идемпотентно обрабатывает повторные вызовы, если пользователь уже состоит в пространстве;
  - Атомарно добавляет участника в `workspace_members`, отмечает статус `accepted` и уведомляет автора приглашения.
